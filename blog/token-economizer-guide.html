What is TokenEconomizer?

The project, hosted in Microsoft's GitHub organization, targets repeated sources of coding-agent waste. Its three mechanisms are micro-skills, tool pruning and failure-loop intervention. These respectively reuse learned repository facts, leave out tools that have not been useful, and redirect an agent when it appears stuck.

That makes it different from a token counter. Counting tells you how much text a model processed; this project attempts to change how the agent works. It is also different from a cheaper model or an API discount: compare the whole completed task, not just the price of one request.

It is worth evaluating if you repeatedly work in the same repository and notice the agent rediscovering setup instructions, carrying unnecessary tools, or retrying the same failed approach. For a one-off task, there may be less repeated work to eliminate.

Install and check the plugin

The example below is for Claude Code. Upstream also documents other agents, with different installation and support boundaries. Check the current supported versions before proceeding. You need a signed-in supported agent and Python 3.10 or newer. Do not assume a newer agent version has already been tested.

1. Keep a local copy of the project

Run this in a terminal, in a directory where you keep development tools:

git clone https://github.com/microsoft/TokenEconomizer.git

Keep that checkout in place. Replace the placeholder below with its absolute path.

2. Install for Claude Code

claude plugin marketplace add /absolute/path/to/TokenEconomizer
claude plugin install tokeneconomizer@tokeneconomizer
claude plugin list

Start a new Claude Code session in the repository you want to work on. Review any plugin permission prompts. The following commands belong in the agent's prompt, not the terminal:

/tokeneconomizer:status
/tokeneconomizer:toolprune refresh-catalog

The first checks plugin status. The second records the available tool catalog. Upstream recommends refreshing that catalog again after Claude Code updates.

3. Inspect changes before relying on them

For a cautious first evaluation, ask the plugin to propose tool-pruning changes instead of applying them automatically:

/tokeneconomizer:config set toolprune=propose
/tokeneconomizer:toolprune

This controls tool pruning, not every plugin mechanism. Read the proposal and upstream settings documentation before applying changes. A successful installation alone does not demonstrate a cost saving.

How to measure cost without ignoring quality

Use a small set of representative tasks: fixing a reproducible bug, adding a bounded feature, and making a change that requires learning the repository. Define the acceptance checks before running either configuration. A lower bill for an incomplete task is not an improvement.

  1. Record the repository commit, agent version, model, plugin revision and relevant settings.
  2. Run a baseline without the plugin, starting from a clean copy of that commit. Keep the task prompt and permissions fixed.
  3. Run the same task with the plugin from another clean copy. Document whether the plugin already has learned state. Keep cold-start and experienced runs separate.
  4. Repeat across tasks and alternate run order. One run can be dominated by caching, a lucky edit or a transient failure.
  5. Review the code and run the same acceptance checks. Include any manual repair time and additional model calls.

Limitations and rollback

The upstream project reports lower mean cost in its benchmark experiments. Those measurements belong to the authors' evaluated configurations and tasks, not to every repository. Consult the original results for the benchmark and quality metrics. This page does not reproduce them as personal test results.

Learned context and pruning can behave differently across agents. Plugin model calls add overhead, and historical repository facts can become stale. Review what changes, especially after repository or agent updates. The model-provider and permission boundaries of your normal agent still matter.

To restore tools that the plugin pruned in a Claude Code repository, use its agent-prompt command:

/tokeneconomizer:toolprune restore

If uninstalling, restore tools in affected repositories first, then use these terminal commands:

claude plugin uninstall tokeneconomizer@tokeneconomizer
claude plugin marketplace remove tokeneconomizer

See upstream instructions for other agents and for handling retained learned state. This guide does not require deleting that state.

Common questions

Is TokenEconomizer an official model or a token-counting website?

No. It is a coding-agent cost-control project. Use its repository and documentation to identify the project rather than assuming any similarly named service is affiliated.

Can I use it with Codex or another agent?

Upstream provides agent-specific instructions. Follow that section and its compatibility notes; do not reuse Claude Code's commands in a different tool.

Should I install it just because it promises savings?

Start with a task where you can measure completion and cost. If the plugin does not improve that workflow, restoring the original setup is a reasonable outcome.
